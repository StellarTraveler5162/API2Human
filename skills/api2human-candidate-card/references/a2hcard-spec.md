# API2Human 面试者角色卡格式规范（a2hcard v1）

- **名称**：API2Human 面试者角色卡 / API2Human Candidate Card
- **后缀名**：`.a2hcard`
- **编码**：UTF-8 纯文本，内容是 Markdown（任何文本编辑器都能打开修改）
- **UTI**：`com.api2human.candidate-card`（遵循 `net.daringfireball.markdown`、`public.plain-text`）
- **版本**：1

角色卡回答的是一个问题：**"在面试里，我能真实地说出口哪些关于我自己的话？"**
它把散落在简历、项目文档、笔记里的信息，整理成面试助手可以直接引用的事实，并标出能力边界，让 AI 不替面试者编造经历。

---

## 1. 文件结构

```
---
a2hcard: 1
name: 张三
role: 高级后端工程师
years: 6
language: zh
updated: 2026-11-03
---

## 一句话定位
……

## 工作经历
……
```

文件由两部分组成：**头部元信息** + **正文章节**。

### 1.1 头部元信息（必需）

以单独一行 `---` 开始和结束，中间每行写一个 `键: 值`，不支持嵌套。

| 键 | 必需 | 说明 |
|---|---|---|
| `a2hcard` | ✅ | 格式版本，目前固定为 `1`。解析器靠它识别文件 |
| `name` | ✅ | 面试中使用的称呼，可以只写姓或英文名 |
| `role` | ✅ | 当前或目标职位，如"高级后端工程师" |
| `years` | 推荐 | 相关工作年限，数字 |
| `language` | 推荐 | 面试语言：`zh`、`en` 或 `zh+en` |
| `updated` | 推荐 | 最后更新日期，`YYYY-MM-DD` |

未知的键必须被解析器忽略（为以后的版本留余地）。

值不确定时（比如简历写"6 年"，但时间线算下来是 8 年），写较保守的值，并在后面加标记：`years: 6 [待确认]`。带标记的元信息不会发给面试 AI。

### 1.2 正文章节

章节用二级标题 `## ` 开头，标题必须是下表中的**中文名或英文名**（大小写不敏感），顺序不限。未知章节保留原文，不报错。

| 中文名 | 英文名 | 必需 | 内容 |
|---|---|---|---|
| 一句话定位 | Pitch | ✅ | 1~2 句话：我是谁、做什么、最拿得出手的一点。自我介绍的开头 |
| 基本信息 | Profile | | 学历、所在城市、当前状态（在职/离职）、到岗时间等 |
| 工作经历 | Experience | ✅ | 按时间倒序，每段一个 `### 公司 \| 职位 \| 起止时间` |
| 项目经历 | Projects | ✅ | 每个项目一个 `### 项目名`，用固定字段描述（见 2.2） |
| 技能边界 | Skills | ✅ | 分三档写清楚：熟练 / 用过 / 了解或没用过（见 2.3） |
| 故事库 | Stories | | 行为面试题用的 STAR 故事，每个一个 `### 主题` |
| 求职口径 | Talking Points | | 离职原因、为什么选这家、期望薪资、职业规划的统一说法 |
| 红线 | Red Lines | | 不能说、要回避的话题，以及被问到时怎么转移 |
| 目标岗位 | Target Role | | 本次面试的公司、岗位 JD 要点、面试轮次与面试官 |
| 表达风格 | Voice | | 说话风格偏好：简洁/详细、口头习惯、要避免的措辞 |

## 2. 章节写法

### 2.1 工作经历

```
### 某生鲜电商公司 | 高级后端工程师 | 2021.03 - 至今
- 负责履约调度系统，团队 8 人，我带 3 人
- 派单服务 P99 从 900ms 降到 120ms
```

每条写**一件可以被追问的事**，尽量带数字。

非雇佣经历（创业、自由职业、进修、照顾家人等）也写成一段，标题写明性质，例如 `### 创业：社区团购项目 | 联合创始人 | 2020.01 - 2020.06`。用户不想主动提的经历，可以不写在这里，但要在「求职口径」里写好被问到时的说法。

### 2.2 项目经历

每个项目用下面的字段，以 `- 字段：内容` 的形式书写，可以省略写不出的字段：

| 字段 | 说明 |
|---|---|
| 背景 | 业务背景、要解决的问题、规模 |
| 我的角色 | 我具体负责什么，团队多大——**区分"我做的"和"团队做的"** |
| 做法 | 关键技术方案和取舍，写到面试官追问两层还答得上的程度 |
| 结果 | 可量化的结果，没有数字就写定性结果 |
| 技术栈 | 用到的技术 |
| 难点 | 遇到的最大困难和怎么解决的 |
| 追问准备 | 预计会被追问的问题，以及我的答法 |

```
### 履约调度系统 Go 重写
- 背景：老派单服务用 PHP，高峰期 P99 900ms，经常超时
- 我的角色：方案设计 + 核心派单链路开发，团队 3 人
- 做法：按城市分片的内存调度队列；批量派单合并 DB 写
- 结果：P99 900ms → 120ms；大促零故障
- 技术栈：Go、Redis、RocketMQ
- 追问准备：为什么不用 Java？——团队已有 Go 基建，内存占用低
```

### 2.3 技能边界

必须分档，这是防止 AI 夸大能力的关键：

```
- 熟练：Go、MySQL（分库分表、慢查询优化）、Redis
- 用过：Java/Spring Boot、RocketMQ
- 了解或没用过：Kafka（只看过原理）、Kubernetes（只会写 yaml 部署）
```

同一档可以写多行。分档是整理者按证据做的保守判断，**不加 `[待确认]`**（否则整档在面试时会消失），需要确认的分档放进提问清单。被问到"了解或没用过"档里的技术时，助手应当诚实回答，再引向相关经验。

### 2.4 故事库

```
### 和上级意见不一致
- S：大促前上级想跳过压测直接上线
- T：……
- A：……
- R：……
```

常见主题：最大的成就、最大的失败、冲突、带人、压力下交付、学习新技术。

### 2.5 求职口径 / 红线

用 `- 问题：说法` 的形式，例如：

```
- 离职原因：想做更大规模的调度系统；不评价前公司
- 期望薪资：先了解岗位级别，再说范围
```

## 3. 真实性标记

角色卡里的每一句都应当是面试者能真实说出口的事实。整理时遇到下面的情况，必须加标记：

| 标记 | 含义 | 面试者要做的 |
|---|---|---|
| `[待确认]` | 从材料里推断出来，但原材料没有明说（如推算的团队规模） | 确认后删掉标记，或删掉这个分句 |
| `[待补充]` | 这个信息很重要，但材料里没有 | 自己补上内容，再删掉标记 |

**带任一标记的分句都不会发给面试 AI**——未经确认的推断不会被引用，缺失的信息也不会被 AI 编出来。

两种标记都可以带提示：`[待确认：简历写 6 年，时间线约 8 年]`、`[待补充：分片键和迁移方案]`。

**标记的作用范围是它所在的分句。** 分句以 `，` `,` `、` `；` `;` `。` 分隔，括号 `（）()「」【】[]` 里的标点不算；`- 字段：` 这样的行首前缀不算分句内容；一行的分句全被删掉时整行删除；标题行里的标记只删标记本身。例如：

```
- 我的角色：负责方案设计和核心派单链路；团队总人数 [待确认]
- 用过：Java [待确认]、Redis（GEO、二级缓存）
- 做法：拆分为 16 个分片；分片键和迁移方案 [待补充]
```

面试 AI 看到的是：

```
- 我的角色：负责方案设计和核心派单链路
- 用过：Redis（GEO、二级缓存）
- 做法：拆分为 16 个分片
```

写卡时，**把事实和不确定、缺失的内容拆成不同的分句**，不要写成"拆分为 16 个分片 [待补充：分片键]"，否则"拆分为 16 个分片"这个事实也会被一起删掉。校验工具会报出标记的数量，`--ai-view` 可以预览面试 AI 实际看到的内容。

`<!-- -->` 注释会被保留，但不会发给面试时的 AI，可以用来记录信息来源，例如 `<!-- 来源：简历.pdf 第 2 页 -->`。

## 4. 解析规则（实现者参考）

1. 去掉 UTF-8 BOM；统一换行为 `\n`。
2. 第一行必须是 `---`。读到下一个单独的 `---` 为止，按第一个 `:` 切分出键和值，两边去空格。
3. `a2hcard` 缺失或不是正整数：不是角色卡。大于本解析器支持的版本：仍然尽量解析，并给出提示。
4. 正文按行首 `## ` 切分章节，章节名去掉首尾空格后和第 1.2 节的中文名或英文名比较（英文名不区分大小写）。
5. 第一个 `## ` 之前的正文内容（如果有）归入"一句话定位"。
6. 发给面试 AI 之前：删除 `<!-- -->` 注释；按第 3 节规则删除带 `[待确认…]` 或 `[待补充…]` 的分句；删除删完后只剩 `- 字段：` 前缀或空白的行；删除带标记的元信息。

## 5. 在 API2Human 中的用法

- **面试资料窗口 → 从文件导入**选择 `.a2hcard`，或直接双击文件。
- 映射关系：
  - 目标岗位 → "目标岗位 JD"栏
  - 求职口径 + 红线 → "补充信息"栏
  - 其他章节 → "我的简历/背景"栏
- 生成角色卡：使用 skill `api2human-candidate-card`，把简历、项目文档等材料交给 AI Agent 整理。
